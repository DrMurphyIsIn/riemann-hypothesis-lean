## What the package proves

For each of 18 certified cells (field K, window L) from rk1/MEMO.md, the theorem `RK2.Asm_<cell>.rk_floor` proves

    published ≤ Qinf

where Qinf stands for inf R_K(g)/‖g‖² over complex g ∈ C_c^∞(−L, L). It is proved from the following hypotheses, each named
and never asserted:

| hypothesis | content | trust class |
|---|---|---|
| `hbe`, `hbo` (kernel cells) | each parity head lies in an outward-rounded integer box \|A_ij − Mz_ij/S\| ≤ w/S | ARB (Arb enclosure of the rk_fz head; rk1) |
| `hAe`, `hAo` (L = 2.25, 2.4) | the head has floor a (verified Cholesky in rk1) | ARB |
| `hD` | λ_D ≥ d | ARB |
| `hC` | ε_C ≤ e | ARB |
| `hchain` | Theorem RK (C1)–(C8): any common floor a of the two head forms gives min(a, λ_D) − ε_C ≤ Qinf | PROVED on paper (rk1/MEMO.md §2); abstract implication in Lean |

The kernel proves everything else:
- the head floors, for **every** real matrix in the box (the PGC instances);
- the rational arithmetic.

Axioms: {propext, Classical.choice, Quot.sound}. There is no `native_decide`, `sorry`, `admit` or `skipKernelTC` anywhere.
The package was checked twice: by the Lean 4.34.1 kernel and by nanoda 37cb87b7, on per-field lean4export exports.

## The new kernel shape: PGC (RK2PGC.lean, Mathlib only, proved once)

A head G (m × m) is known only through its box. The certificate is written in base X = 2^B with offset digits:
- row i of the box centre M is one natural number;
- column k of a rounded Cholesky factor L is one natural number.

`decide +kernel` evaluates two checks:
- **`paramsOK`, once per instance.** Each column is lower triangular, and every L entry lies in [−K, K) (one bit-mask test).
- **`blk`, per row.** It forms the packed residual T_i = pack(M_i) − cS·X^i − Σ_{k≤i} L_ik·pack(col_k), which is an exact ℤ
  identity for row i of R = M − cS·I − LLᵀ. It then checks that T_i + E·Σ X^j is in [0, X^m) and that all its digits are
  < 2E (one bit-mask test).

The proved lemma `digits_unique` (unique signed base-X decoding) then gives |R_ij| ≤ E. From that, `pgc_floor` gives

    ((cS − m(w + E))/S)·Σxᵢ² ≤ xᵀGx   for every real G in the box and every x.

The lemma needs no symmetry of the box centre. Each row costs O(m) big-number operations, against RK-1's `floor_of_rowsum`,
which costs O(m) kernel steps per entry. That change made heads with m = 583–983 feasible.

## Files

- `RK2PGC.lean`: the PGC definitions and soundness proof.
- `<field>_L<L>_<parity>.lean`: the generated instances (data + block checks + `floor`, `floor_pub`).
- `Asm_<cell>.lean`: the cell assemblies.
- `Field_<field>.lean`: the aggregators.
- `T4_exp.lean`: e^{L²/8} brackets, the factor of K_2 inside ε_C. The Lean text was GENERATED by Telperion's Python emitter
  `exp_enclosure` (unmodified) and uses only Mathlib's `Real.exp_bound`; there is no Telperion Lean dependency.
- `Refusals.lean` plus `RK1Floor.lean`, `EP5_E1_even_neg.lean` and `DH_L175_*_neg80.lean`: RK-1's kernel refusals, copied
  verbatim with matching md5s and rebuilt here.
- `CTRL_*`: the must-reject controls.
- `scripts/`: the generators (pgc_emit.py, asm_emit.py, controls.py, exp_emit.py).
- `MANIFEST.md`: the md5 of every file.

The instances are large (up to 150 MB of source) and are regenerable from rk1/out heads with `scripts/pgc_emit.py`. The MANIFEST
records their md5s.

## How to check

Every path in the package is relative to the package root. External tools come from the environment (scripts/env.sh):
`LEAN_ENV` (a built Lean v4.34.1 + Mathlib d13f23b project with its own .lake, e.g. an APFS clone of rec1/kr_build; `lean` of
that toolchain on PATH), `LEAN4EXPORT` (default `lean4export`), `NANODA` (nanoda 37cb87b7, default `nanoda_bin`), and the optional
`LEANLOCK` (a job-serialising wrapper). Compile with `scripts/run1.sh NAME` (plain `lean -o build/NAME.olean lean/NAME.lean`, no
lake) in this order:
1. `RK2PGC`, `T4_exp`, `RK1Floor`;
2. every instance `<field>_L<L>_<parity>` and `EP5_E1_even_neg`, `DH_L175_{even,odd}_neg80`;
3. every `Asm_<cell>`;
4. `Field_<field>` and `Refusals` (they print the axioms).

Then export and check with `scripts/run_export.sh <Field module> <tag> <RK2.Asm_<cell>.rk_floor ...>`. It runs lean4export, then
nanoda with permitted axioms {propext, Classical.choice, Quot.sound}. It ABORTS with FAIL when the export rc is non-zero, when
the export is under 1 MB, or when nanoda's rc is non-zero or it reports "Checked 0 declarations" (`scripts/check_export.sh`;
`scripts/test_export_guard.sh` tests it). A guard is needed: nanoda passes an empty export with rc 0. nanoda needs about 21 GB
of RSS for the Refusals export (the EP5 refusal, m = 215) and 1–4 GB for the field exports.
